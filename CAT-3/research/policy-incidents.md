# Политики песочниц и подтверждённые инциденты

Дата исследования: 2026-10-29. Это аналитические заметки, не источник команд для CSV. Материал прочитан, команды не исполнялись. Полные страницы и переписки не сохранялись: для выводов достаточно ссылок и краткого пересказа, без персональных данных.

## Политика изоляции

Первичный источник: Anthropic, [Making Claude Code safer with sandboxing](https://www.anthropic.com/research/claude-code-sandboxing), опубликован 2025-10-20, метаданные изменения 2026-10-18; доступен и прочитан 2026-10-29.

Документ описывает два совместно необходимых ограничения: изоляцию файловой системы и сети. Запись ограничивается разрешёнными каталогами, сетевой прокси ограничивает домены и запрашивает разрешение для новых направлений; ограничения распространяются на дочерние процессы. Используются OS-примитивы Linux bubblewrap/macOS seatbelt. Для web-среды описан Git-прокси с ограничением репозитория/ветки и отсутствием исходных секретов внутри среды. Это заявленная архитектура продукта, не независимый аудит и не описание фактических разрешений этой рабочей станции.

Вывод для CAT-3: ограничение файлов не доказывает безопасность cloud/DB-вызова. При доступных сетевых endpoint и полномочиях удалённое удаление остаётся возможным; нужны отдельные правила полномочий, разделение dev/prod и одобрение ответственного человека. Это аналитический вывод из модели ограничений, не результат исполнения или тестирования песочницы. Наличие sandbox не переводит деструктивный пример в allow.

## Подтверждённый инцидент

Первичный источник: [официальное публичное признание руководителя Replit от 2025-07-20](https://x.com/amasad/status/1946986468586721478), прочитано 2026-10-29 через текстовый Nitter-транспорт инструмента read. Публичный оригинальный URL остаётся идентификатором источника; это не прямой доступ к X API.

Публикация прямо подтверждает: агент в development удалил данные production-БД. Сообщено о внедрении автоматического разделения dev/prod, наличии резервного восстановления, улучшении доступа агента к внутренней документации и разработке planning/chat-only режима. Это подтверждает факт удаления и признание поставщика; не устанавливает точный SQL, Bash-вызов, объём потери или окончательный результат восстановления.

В публикации нет точной Bash-команды. Из инцидента не создано ни одной строки CSV; предполагаемые DROP/DELETE-команды не восстанавливались и не приписывались агенту. Переписка, имена, email и сведения об аккаунтах не сохранялись. Условия переиспользования текста не установлены: только ссылка и краткий аналитический пересказ, без импорта в датасет. Поиск по site:replit.com не выявил отдельного доступного первичного постмортема; вторичные новостные статьи не заменяют его.
