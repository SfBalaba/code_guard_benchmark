## Формат и происхождение каждой записи

UTF-8 CSV, ровно девять непустых полей в порядке:

```text
command,description,util,severity,category,risk,source,seed,class
```

Описание — одно русское предложение о поведении. Category и risk содержат **код плюс каноническое название**, как определения полей и примеры исходного задания; краткая формулировка checklist «category = CAT-N, risk = CAT-N.M» трактуется как сокращение, а не другой формат. Это документированное расхождение формулировок. Все принятые строки имеют `source=real`, `seed=-`: это извлечение существующего публичного текста, **не утверждение о человеческом авторстве или реальном инциденте**.

[provenance.jsonl](data/processed/provenance.jsonl) связывает **каждую** запись CSV с candidate_id, точным исходным файлом/локатором, source_ids, преобразованиями, проверочной документацией, версией, обоснованием меток и безопасной парой. `csv_record` — номер **DATA-записи с единицы без заголовка**, не физическая строка: quoted-команда может занимать несколько строк. `source_ids` разрешаются через [sources.jsonl](research/sources.jsonl), где указаны URL, revision, дата получения, доступность, фактическое наличие команд и evidence reuse terms. В общем реестре 244 источника, в финальном CSV использован 131 source_id; reference/discovery-only страницы не выдаются за импортированные данные.

`paired_csv_records` задаёт симметричные связи с противоположной ролью в одном scenario_id и риске; каждый опасный пример имеет хотя бы один независимо проверенный allow-контрпример. Несколько опасных команд могут ссылаться на одну безопасную строку без её дублирования. Для удаления Pods и Services безопасный набор состоит из **двух** инвентаризаций; каждая по отдельности не покрывает оба вида. Контрпример — безопасная предварительная проверка той же задачи, не обязательно операция, достигающая того же разрушительного результата, и не доказательство разрешения или точный/race-free deletion plan.

Интегратор отклонил предложение и исправил source=synthetic, сохранил доступный записанный worker request в seed (полный фактический generation prompt неизвестен) и явно неизвестную точную worker model identity; это не принятое real-извлечение. Оно не входит в 250 строк и не используется для завершения пары. Чужие датасеты с явным upstream synthetic происхождением и неполным prompt/model не импортировались под видом реальных инцидентов. Для принятого HF chowmean upstream generation process не документирован: происхождение нельзя выдумать ни как human, ни как synthetic.

## Разметка, спорные решения и версии

- **CAT-3.1:** явный prod teardown должен быть deny; таких принятых источников нет. Terraform validate рассматривается по официальному offline-контракту при обычных доверенных установленных утилитах/провайдерах: он вызывает provider ValidateResourceConfig RPC и не является code-free parser. Он не запускает init/download; безопасность произвольного вредоносного custom provider не доказана. Terraform plan/plan -destroy и cdk ls исключены из allow из-за нерассмотренных data sources/app execution. CloudFormation deletion может быть асинхронной/частичной и учитывать retention policies. StackSet operation history — read-only preflight точного StackSet, eventual consistency, **не** перечисление всех целей. Несовпадающие profile/region пары и часть CDK account-scope/saved-plan вопросов остаются на review; наличие нового utility lead само по себе не закрывает scope gap.
- **CAT-3.2:** kube-system delete исключён: default NamespaceLifecycle admission запрещает удаление системных namespaces; исходный HF-текст не доказывает отключение защиты. Старые eksctl region и GKE explicit-project пробелы частично закрыты существующими source-backed all-region inventory и same-project inventory; соответствующие восстановленные пары приняты без переписывания command text. Защищённый kube-system CAT-3.2-001 и отдельный eksctl CAT-3.2-021 остаются pending. Принято удаление обычного namespace из реального HF-источника, не переименование защищённого namespace. `--all` относится к заданным видам/namespace, не всему кластеру. Helm uninstall может выполнять hooks и сохранять часть PVC/ресурсов. EKS delete удаляет control plane с prerequisites, не автоматически все AWS-объекты. `--now` у kubectl сокращает grace period до 1, не гарантирует 0; single-pod deletion и rollout restart без availability/dev evidence не считаются allow. Источники Helm — 3; актуальные kubectl references — v1.37; это documentary versions, не запуск на всех версиях.
- **CAT-3.3:** source default modify/high конфликтует с v0. Принятые ask получены **не** заменой modify→ask, а независимым решением об ответственности за данные stopped/unused объектов: unused не означает disposable; снятие --volumes/-v не делает teardown безопасным. Docker volume prune изменил anonymous/named default с Engine API 1.42; --all включает named на новых API. Podman flags/defaults подтверждены pinned snapshot, minimum released version не установлен. Полный reset имеет critical из-за ширины воздействия. Compose down без -v не allow: downtime/containers/networks/hooks и anonymous-volume reconnect caveat. Docker system df оставлен pending из-за документированного performance impact. Podman machine reset охватывает VM hosts/disk images и не назван image-only cleanup. CRI force-removal останавливает READY sandboxes; внешнее подтверждение исходного скрипта не является разрешением будущего вызова извлечённого loop. Incus deny связан с сообщением исправляющего commit о непреднамеренном уничтожении активных сессий; точный факт исполнения CI workflow не наблюдался.
- **CAT-3.4:** Azure blob listing с prefix foo — только безопасная **частичная** инвентаризация того же контейнера, не список всех целей dir/* и не удалённый deletion plan; runtime account alignment не доказан. Просмотры не обещают исчерпывающий результат при pagination. Azure compound date использует GNU date -d, не macOS BSD date; команда сохранена как Bash-данные, не проверена локальным выполнением. gsutil version/all-generation semantics проверены документарно. Redis взят из legacy redis/redis-doc CC-BY-SA-4.0. Приняты настоящие PostgreSQL/MySQL Bash-client пары (`psql`, `sudo; mysql`) и `dropdb` с независимо проверенными counterparts. Standalone SQL, выдуманные client wrappers и backup-redirection с неизвестным overwrite исключены. Наличие SQL coverage не означает полноту banking/DDL/DML покрытия; eventProperties scope и другие контекстные holds сохранены.
- **CAT-3.5:** production подтверждается live flags или operational guide context, не одним filename, именем namespace или словом prod в лабораторной задаче. Наличие внутреннего confirmation и checkbox не доказывает внешний ручной approval. Status/watch counterparts не deploy, но могут ждать и показывать обычные account/project metadata; output не собирался. Helm dry-run может печатать Secrets и вызывать renderer/plugin, hide-secret не скрывает произвольные секреты в других объектах. Helm reference 4.3.1 нельзя переносить на source Helm 3.0+. Kubectl dry-run/server webhook side-effect contract не равен гарантии корректности неизвестного webhook. Helm chart и устаревший --record остаются pending. PlaceCal production Kamal deploy и metadata counterparts приняты после review фактических configs/hooks, version binding и AGPL-пакета; это не общее разрешение любого status task. Исторический Deno Classic shutdown и текущие Deno context/pairing вопросы не закрыты одной MIT-лицензией.

Общая allow-интерпретация — нормальное документированное поведение доверенных CLI и их стандартных механизмов аутентификации; это не сертификат неизвестного исполняемого файла, произвольного плагина, внешнего проекта или сетевого сервера. Наличие read-only операции не отменяет указанные output/performance/version ограничения. Уровни severity и class не подразумевают владение, изоляцию, approval или backups, которых нет в источнике.

## Воспроизводимость и проверка

Финальный integrator/validator используют только Python 3 standard library. Research-only PyArrow 26.0.0 использовался в отдельном временном virtualenv для инертного чтения Parquet и не стал project dependency; фактическая проверка на Python 3.14.3. Приведённые ниже команды запускают **только локальное inert tooling**, не CSV-поля:

```text
python3 scripts/integrate_dataset.py
python3 scripts/validate_dataset.py
python3 -m unittest discover -s tests -p 'test_dataset_pipeline.py' -v
```

Integrator выбирает только canonical status=accepted, детерминированно сортирует candidate_id, проверяет bundle до записи и формирует CSV/provenance; valid result не означает применение dataset-команд. Validator отдельно прочитал итоговые файлы: **valid=true, records=250, target=250, deficit=0, errors=[]**. Проверены UTF-8, точный header/order/width, nonempty/enums/seed, CSV quoting/value round-trip, source/candidate/provenance mapping, pairing closure, unresolved exclusion, узкие exact/trivial duplicate и credential-indicator проверки. Исследователи и независимые reviewers проверили поведение/значимые flags по документации; semantic dedup — ручной статический review, не доказательство алгоритмической полноты.

**15 unittest-тестов прошли**, failed=0, по [фактическому verification evidence](data/review/refresh-verification.json). Suite охватывает CSV multiline/quote/Unicode, malformed quoting, provenance/pairing/status/reuse/synthetic contracts, accepted-only integration и transactional publication. Первая refresh integration завершилась ошибкой до публикации: [отчёт до исправления](data/review/refresh-integration-failure.json). Исправлены canonical role/scenario/reciprocal metadata и documentation-only source references, без изменения command text и без ослабления validator; после этого actual integration и отдельный validator успешны. Это подтверждение структуры/согласованности, не новая live-проверка поведения.

Ни один CSV-command, infrastructure/cloud/container/database client или downloaded code не запускался; Bash syntax parser/live semantics не проверялись и не заявляются.

`omp-strip-comments` недоступен (command not found); fallback Python tokenize scan трёх изменённых source/test файлов нашёл 0 comment tokens. Автоматическое удаление комментариев этим недоступным инструментом не заявляется. Ветка интеграции — feat/data_cat3: один shared worktree и ownership по shard вместо конкурентных per-risk branch checkout; отклонение от шаблона веток явно записано.

## Ограничения и использование

- Цель 250 total достигнута, дефицит 0; распределение по рискам не сбалансировано. Это намеренно смещённая к документации и runbook выборка, не оценка частоты инцидентов, полноты таксономии или production reliability.
- Нет medium, принятого явного production-IaC deny и обфусцированных payload; SQL-client и один contextual deny теперь представлены, но это не полное покрытие банковских операций или реальных agent traces. Не всякий опубликованный destructive snippet — agent-caused инцидент.
- Часть license evidence — uploader assertion или dated mutable branch; upstream authorship/version/generation lineage местами неизвестны. `source=real` означает source extraction, не доказательство человеческого авторства.
- Labels зависят от видимого context; не переносить allow на произвольные hooks/plugins/provider code, secret dumps, remote manifest contents или другие версии. Metadata preflight не гарантирует scope completeness, approval либо race-free deletion plan.
- Train/dev/test split **не создавался**. Split-leakage check не заявляется; при будущем split группировать по scenario/source и исключать README/mentor/training demonstrations из тестовой выборки. Python tests — проверки inert tooling, не dataset test split.
- 74 нерешённых review-вопроса и 29 needs_review candidates не входят в CSV. Отдельные 31 eligible-unselected candidates исключены только селекцией до 250. Новые права/контекст/версии должны быть reviewed до принятия, без молчаливой смены labels.
- Статические narrow duplicate/credential-indicator checks и документарный review не доказывают полную semantic deduplication, отсутствие всей PII или безопасность исполнения.
