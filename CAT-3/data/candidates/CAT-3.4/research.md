## Фактический результат

Предложены **30 парных записей со статусом candidate**: 18 ask/critical (опасные), 12 allow/low (контрпримеры), deny — 0. Это ещё не accepted: независимая разметка и интеграция принадлежат родителю. Дефицит относительно 250 при принятии всех 30 — **220**; фактический accepted count определяет интегратор. Ещё одна лицензированная команда dropdb имеет needs_review из-за отсутствующей пары и в эти 30 не входит. Вторая запись review queue — URL-only lead без сохранённого текста команды: для SQL gist лицензия не подтверждена.

Покрыты: S3 recursive rm с исключением расширения/поддерева и force rb; DynamoDB delete-table; GCS удаление префикса/бакета/всех версий без удаления бакета; Azure blob delete-batch (префикс, временное условие с видимой подстановкой date, bracket wildcard), az storage remove с рекурсией и составными фильтрами, удаление контейнера и файлового ресурса; Redis FLUSHALL и независимый подсчёт SCAN. Утилиты: aws, gsutil, az, date, redis-cli, wc; dropdb только review. Отдельные SQL исключены; валидных лицензированных SQL-вызовов shell-клиента с безопасной парой в предложенном наборе нет. Банковские transactions/accounts/cards не найдены, названия искусственно не подставлялись; такие опасные примеры должны оставаться critical.

## Разметка и безопасность пар

Сценарии двусторонние, многие-к-многим внутри одной задачи, без дублирования одинаковой безопасной строки для каждого опасного варианта. Наличие общей scenario_id не означает, что листинг является точным планом удаления. Azure prefix foo инвентаризирует тот же контейнер, но не покрывает dir/*; это намеренно записано в evidence_context. Обзор контейнеров/файлов — другой этап диагностики, не разрешение на очистку.

Каждый allow — отдельная операция инвентаризации, не опасная команда с убранным флагом. Официальные учебные fixtures дают видимый контекст условных метаданных, без чтения содержимого, выгрузки секретов, внешнего адресата или перенаправления в файл. Не заявляется, что произвольные реальные object names/metadata никогда не бывают чувствительными. Исключены `ls -L` с ACL/custom metadata, dumps с `>` (неизвестный overwrite/утечка), SELECT * без контекста, KEYS * с блокировкой, непрозрачный `some_program | gsutil ... -I`, команды с внешними payload files и сгенерированные wrappers. Redis counterpart использует SCAN и wc: наружу выводится только число, возможны повторы и нагрузка, это не согласованный snapshot. Object listing и API calls могут тарифицироваться; low не означает абсолютно нулевые расходы.

Для опасных команд ask выбран из-за отсутствия контекста одобрения, ответственности и резервирования, а не потому, что любое удаление обязательно deny. Critical — исходный дефолт CAT-3.4 и потенциальная массовая потеря данных, не выдуманное доказательство отсутствия recovery. Нет предположений production, изоляции или бэкапов. Banking-покрытие отсутствует, правило critical не ослаблено. Все source=real, seed=-; модельные synthetic commands не создавались, prompt/model не нужны. Перевод descriptions и rationale — аннотация, не генерация команды. Sampling не применялся, random_state=not_applicable; split не создавался.

## Достижимый объём и оценки

Наблюдаемый объём — 30 парных proposals, 1 лицензированный unpaired review command и 1 URL-only license/syntax lead. Это не доказательство глобального исчерпания интернета. Рассмотренные небольшие official example sections дали десятки, не 250 смысловых записей; дальнейшее простое варьирование имён, bracket masks, -m, whitespace не считается расширением. SQL, MySQL, банковские данные и облачные версии/retention остаются значительными пробелами.

**Estimate, не измеренное время:** для дополнительного целевого поиска по licensed SQL client scripts и GCS/Azure modern CLI с независимыми counterpart fixtures — 4–8 человеко-часов research, 2–4 часа аннотации и проверки reuse, 1–2 часа независимого review/integration; предположение — доступные небольшие репозитории без bulk gated corpus. Ожидаемый дополнительный usable yield **10–35** после удаления дублей — оценка, не обещание 250. Для текущего шарда независимая review/integration **estimate 1–2 часа**, в особенности API-version caveats, Redis share-alike attribution, Azure partial-inventory pairing и глобальные near-duplicates. Фактическое время выполнения не измерялось.

Sandbox policies и подтверждённые agent-caused incidents обрабатывает родитель глобально; ни официальные примеры, ни HF synthetically created incidents не представлены здесь как реальные agent incidents. Cloud/container/DB клиенты, dataset commands, downloaded code, source/eval не запускались. Выполнялось только чтение публичных источников и инертная запись JSON/текстов. Builds, tests, linters, formatters и проверки готового шарда не запускались; финальная static QA принадлежит интегратору.
